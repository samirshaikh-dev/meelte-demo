## 5. Implementation prompt

Here is the prompt I would give your coding agent to build the initial UI.

# Meelte HR Dashboard — UI-First MVP

Build a clean, minimal, professional HR recruitment dashboard for Meelte.

## Objective

Create an internal HR interface that allows authorised HR users to manage job postings and view candidate information collected through the Meelte Careers page.

This is a UI-first MVP. Focus on completing the frontend experience before implementing backend integrations.

## Scope

Build three main sections:

1. Dashboard
2. Job Management
3. Candidates

### Dashboard

- Total registered candidates.
- Total active jobs.
- Total applications.
- Total expired jobs.
- Recently added candidates.
- Recently created jobs.

### Job Management

- Jobs listing table.
- Create job form.
- Edit job form.
- Publish/unpublish actions.
- Archive and restore actions.
- Expire job action.
- Delete with confirmation.
- Status indicators: Draft, Active, Expired, Archived.

Job fields:

- Job title
- Department
- Employment type
- Workplace type
- Location
- Job description
- Responsibilities
- Requirements
- Salary range (optional)
- Application deadline
- Job status

### Candidates

- Candidates listing table.
- Search by name, email and phone.
- Filter by applied job.
- View candidate details in a drawer or modal.
- Show registration date.
- Show applied jobs and application dates.

Candidate data fields for the initial application UI:

- Full name
- Email
- Phone
- Password (authentication only; never store plaintext passwords)
- Resume (optional if supported in the initial form).

## Candidate application experience

On the public Careers page:

1. Candidate clicks Apply Now.
2. Candidate registers or logs in.
3. Candidate submits the application.
4. Candidate details and application are made available to HR.

Do not build a candidate dashboard or candidate self-service profile portal.

Keep the candidate data model extensible so a dedicated candidate portal can be introduced later.

## UI/UX direction

- Minimal, modern SaaS interface.
- White surfaces with subtle neutral backgrounds.
- Professional typography.
- Consistent spacing and alignment.
- Compact, readable tables.
- Clear page hierarchy.
- Restrained accent colour.
- Subtle borders rather than heavy shadows.
- Responsive desktop and mobile layouts.
- Avoid unnecessary animations, gradients, decorative charts and oversized cards.

## Important constraints

- Do not build payroll, attendance or employee management.
- Do not build a separate candidate dashboard.
- Do not overcomplicate recruitment workflows.
- Use realistic mock data for frontend development.
- Keep components reusable.
- Maintain clean folder organisation.
- Ensure all buttons and UI actions have meaningful interactions.
- Do not claim backend persistence when using mock data.

## Delivery

Complete the dashboard layout, navigation, dashboard overview, job management, job creation/editing and candidate listing/detail views.

Prioritise usability, visual consistency and a production-quality interface over adding unnecessary features.

My suggested development order: Dashboard layout → Jobs listing → Create/Edit Job → Candidates listing → Candidate details.

This gets you a complete, presentable HR dashboard before spending time on authentication, database and application integrations.
