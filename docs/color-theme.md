# MEELTE (classico) — Color Theme Reference

This document describes the color system that the **classico** Flutter app (`meelte_user`) uses today. It documents the existing implementation only; nothing in the app was changed to produce it. Recommendations are kept apart, in [section 9](#9-inconsistencies-and-recommendations).

The admin panel (`meelte_panel` / `meelte_admin`) is a separate repository and is **not** covered here.

**Scope of the analysis (2026-10-27)**

- All 231 Dart files under `lib/` were scanned for `Color(0x…)`, `Color.fromARGB/fromRGBO`, `Colors.*` and `AppColors.*`. The key screens and widgets were also read by hand.
- Platform launch and splash settings were checked: `pubspec.yaml`, Android `res/values*`, iOS `LaunchScreen.storyboard`, and `web/`.
- The static pages in `public/` are covered separately in [section 6](#6-theme-modes), because they are a second, independent color system.
- Not analyzed:
  - colors inside image, SVG, Lottie/JSON and shader assets in `assets/`
  - colors that Material derives at runtime from `ColorScheme.fromSeed`
  - colors set by third-party packages
- `meelte_website/` contains no HTML or CSS. `functions/` contains no UI.

---

## 1. Overview

The app has a **single light theme** built around a **purple brand color, `#6D3BB3`**, on very light, slightly violet-tinted backgrounds (`#F8F5FF`) and white cards. Text is a near-black blue-grey (`#1F1F28`) with a cool grey secondary color (`#6B7280`).

Accents come from three places:

- an **amber/orange** family for coins and highlights
- standard Material **status colors** (green, orange, red, blue) for feedback
- **purple gradients** (dark → lighter purple) on screen headers, the profile and coins screens, and the auth screens

The visual character is soft and friendly:

- rounded white surfaces with light shadows
- a strong purple used sparingly for primary actions, selection and headers
- a darker, more saturated "royal purple" world on the login/onboarding screens

In practice the app does **not** consume one consistent token set. A central token class exists (`AppColors`), but most screens hardcode hex values. Several purple families are used side by side (see [section 9](#9-inconsistencies-and-recommendations)).

## 2. Theme Architecture

### 2.1 Where colors are defined

| Layer | File | What it holds |
|---|---|---|
| Design tokens | [`lib/core/theme/app_colors.dart`](lib/core/theme/app_colors.dart) | `abstract final class AppColors`: 98 `static const Color` tokens, 2 `LinearGradient`s and 1 helper function (`primaryWithAlpha`) |
| Material theme | [`lib/core/theme/app_theme.dart`](lib/core/theme/app_theme.dart) | `AppTheme.light`: a `ThemeData` (Material 3) built with `ColorScheme.fromSeed` plus per-component themes |
| Typography | [`lib/core/theme/app_text_styles.dart`](lib/core/theme/app_text_styles.dart) | `AppTextStyles`: text styles that carry `AppColors` text colors |
| Barrel | [`lib/core/theme/theme.dart`](lib/core/theme/theme.dart) | Re-exports colors, theme, spacing, radius, text styles and durations |
| App entry | [`lib/main.dart:235`](lib/main.dart:235) | `MaterialApp.router(theme: AppTheme.light, …)`. There is no `darkTheme` and no `themeMode`. |

There are no CSS variables, no Tailwind setup and no theme provider beyond Flutter's `ThemeData`. The "design system" is the `AppColors` class plus `AppTheme.light`.

### 2.2 `ColorScheme`

[`app_theme.dart:15-23`](lib/core/theme/app_theme.dart:15):

```dart
ColorScheme.fromSeed(
  seedColor: AppColors.primaryMid,   // #6D3BB3
  brightness: Brightness.light,
  primary: AppColors.primaryMid,     // #6D3BB3
  onPrimary: Colors.white,
  secondary: AppColors.accentOrange, // #F59E0B
  error: AppColors.error,            // #D32F2F
  surface: Colors.white,
);
```

Every other `ColorScheme` role (tertiary, containers, outline, surface tints and so on) is **generated by Material from the seed**. Those values are not in the source, so they are not listed here.

No widget in `lib/` reads `Theme.of(context).colorScheme` directly (0 matches). The generated roles only reach the UI through Material widgets' own defaults, for example switches, progress indicators, text buttons and dialogs.

### 2.3 How colors are consumed (measured across `lib/`)

| Mechanism | References | Distinct values | Files |
|---|---:|---:|---:|
| `AppColors.<token>` | 331 | 39 tokens | 34 |
| Raw `Color(0x…)` literals outside `app_colors.dart` | 560 | ~145 unique hex values repo-wide | 63 |
| `Colors.*` (Material palette, incl. `.shadeNNN`) | 531 | 33 names/shades (`white70`, `black54` etc. counted under their base color) | — |

So **raw hex literals outnumber token references**. Of the 101 `AppColors` members, **62 are never referenced** as `AppColors.<name>` anywhere in `lib/`; see [9.6](#96-unused-tokens).

## 6. Theme Modes

- **Light only.** `MaterialApp.router` sets only `theme: AppTheme.light` ([`main.dart:235`](lib/main.dart:235)). There is no `darkTheme` and no `themeMode`, and nothing reads `platformBrightness`. The app looks the same when the device is in dark mode.
- **Native launch screens** are white: `flutter_native_splash` uses `color: "#FFFFFF"`, including Android 12 (`pubspec.yaml:84-91`), and the iOS `LaunchScreen.storyboard` background is white.
  - Android has `values-night*/styles.xml`. These are the Flutter template launch themes using `?android:colorBackground`; no app-specific dark colors are defined there.
  - `web/index.html` contains light/dark splash `<source>` images generated for web.
- **In-app splash** (`MeelteSplashOverlay`) is always **dark** (`#0B0F17` / night-sky gradient), whatever the system mode is.
- **Web manifest:** `web/manifest.json` has `background_color` and `theme_color` set to `#0175C2`. This is Flutter's default template blue, not a brand color *(inferred: never customized)*.

### Separate system: static web pages in `public/`

These are not part of the Flutter theme. They are listed so they are not mistaken for it.

- `public/acc-dlt.html` (web account deletion):

## 7. Color Usage Guidelines

These conventions already exist in the code. They describe what the source states or consistently does; they are not new rules.

1. **Import the barrel and use tokens.** `theme.dart` exists so that screens import `AppColors`, `AppTheme` and the other tokens from one place. `app_text_styles.dart` states: "Never hardcode values like `TextStyle(fontSize: 16, …)`. Use `AppTextStyles.h2` or `AppTextStyles.body` instead."
2. **Primary purple `#6D3BB3`** is for primary actions, selection, focus, the FAB and the user's own content (own chat bubble).
3. **White on purple** for content placed on primary or gradient backgrounds (`onPrimary`, `AppTextStyles.button`).
4. **Text hierarchy:** `textPrimary` for headings and body, `textSecondary` for captions and meta, `textHint` for hints and micro labels.
5. **Feedback through `SnackbarUtil`.** Success, error, info and warning each map to their `AppColors` status color.
6. **Purple gradient headers** with rounded bottom corners are the standard top of most tab screens. Material deep-purple gradients are used on the auth and notification screens.
7. **Light purple tints** (`#F3EEFF` family) sit behind purple icons in tiles and chips.
8. **Red family** is reserved for destructive actions, errors, missed calls and likes.

## 8. Accessibility Notes

- normal text needs **4.5:1**
- large text (≥ 18pt, or ≥ 14pt bold) needs **3:1**
- non-text UI parts (borders, icons) need **3:1**

## 9. Inconsistencies and Recommendations

**9.1–9.8 describe what exists. 9.9 lists suggestions.** No code was changed.

### 9.1 Several purple systems

At least five purple families are used side by side:

1. **Token brand:** `#6D3BB3` / `#5B2E91` / `#8E5CE6`.
2. **Untokenized "royal purple":** `#6B2C70`, 34 uses. Also the brand color of `public/acc-dlt.html`.
3. **Header-gradient purple:** `#7A45C4`, 17 uses, always paired with `#5B2E91`.
4. **Material deep purple:** `#4A148C`, `#6A1B9A`, `#7B1FA2`, `#9C27B0`, `#673AB7`. Used for auth headers, auth focus, notifications, blocked friends, and `Colors.deepPurple`.
5. **Auth button violet:** `#7E3FF2` / `#5B21B6`. **Login dark violets:** `#2C0E3F` / `#4A1F5F`. `#4A1F5F` also exists as the unused legacy token `primaryAlt`.

### 9.2 Two "primary gradients"

- The token `primaryGradient` is `#5B2E91 → #8E5CE6` and is referenced twice (as `primaryGradientVertical`).
- The hardcoded `#5B2E91 → #7A45C4` is used 17 times.
- A third gradient, `#4A148C → #6A1B9A → #7B1FA2`, plays the same header role on other screens.

- `ColorScheme.secondary` is amber `#F59E0B`. Material widgets that pick `secondary` therefore turn amber, which may be unexpected *(inferred; not checked per widget)*.

### 9.8 Platform mismatches

- `web/manifest.json` uses Flutter's default `#0175C2`.
- The native launch screen is white, while the in-app splash that follows is dark (`#0B0F17`). Users may see a white → dark flash on launch *(inferred; not checked on a device)*.

### 9.9 Recommendations (not applied)

1. Decide which purple family is canonical (`#6D3BB3` vs `#6B2C70` vs the Material purples). Then give `#6B2C70`, `#7A45C4` and the header gradient a token each, so one change updates every screen.
2. Replace raw literals that already have a token, starting with `primary`, `textPrimary`, `textSecondary`, `textHint` and `primaryDark`. The four form, profile and coin files in 9.3 hold 28% of all raw literals.
3. Pick one border grey (`#ECECEC` or `#E5E7EB`) and one page background, and update the theme or the shared widgets to match.
4. Remove or merge duplicate and unused tokens, or start using them (for example `liked` for likes, `otherMessage` for incoming bubbles).
5. Accessibility:
   - darken the hint/placeholder grey (`#9CA3AF`)
   - darken the warning snackbar background, or use dark text on it
   - use `error` `#D32F2F` instead of `#F44336`/`#EF4444` for destructive text
   - strengthen input borders to at least 3:1, or rely on another visible boundary
6. If a dark mode is ever wanted, nothing exists yet. It would need a `darkTheme` plus token usage first, because hardcoded colors won't switch.
7. Set brand colors in `web/manifest.json` if the web build is used.
